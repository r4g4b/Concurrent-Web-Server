Server online

Web server is now running …

You are looking at a static page delivered by a concurrent HTTP/1.0 server written from scratch in C, using nothing but raw POSIX sockets, processes and signals.

What just happened

  1. Your browser opened a TCP connection, and the server's accept() call returned a new client socket.
  2. The server called fork(). A child process took over your connection while the parent went straight back to accepting new clients.
  3. The child read your request line (e.g. GET / HTTP/1.1) and checked that the method is GET and the path contains no ...
  4. The path / was mapped to index.html inside the served directory, the file was opened with open(), sized with fstat() and read into memory.
  5. The child wrote back an HTTP/1.0 200 OK header with the right Content-Type and Content-Length, followed by this file, then closed the socket and exited.
  6. The parent's SIGCHLD handler reaped the finished child with waitpid(-1, NULL, WNOHANG), so no zombie processes pile up.

Features

  • Fork-per-request concurrency: every connection runs in its own process, so a slow or crashing request can't affect others.
  • Zombie-free: terminated children are cleaned up asynchronously by a signal handler.
  • Static file serving: HTML, CSS, JavaScript, images and plain text from any directory you choose.
  • MIME detection: Content-Type is inferred from the file extension, falling back to application/octet-stream.
  • Directory traversal protection: any URL containing .. is rejected before the filesystem is touched.
  • Error handling: 404 Not Found for missing files and 405 Method Not Allowed for anything other than GET.
  • Fast restarts: SO_REUSEADDR lets the server rebind its port immediately after being stopped.

Try it from a terminal

# Build and start the server on port 8080, serving ./www
gcc -o server server.c
./server 8080 ./www

# Inspect the response headers
curl -v http://localhost:8080/ -o /dev/null

# Error cases
curl http://localhost:8080/missing.html
curl --path-as-is http://localhost:8080/../etc/passwd
curl -X POST http://localhost:8080/

# Several concurrent requests, each handled by its own process
for i in 1 2 3; do curl -s http://localhost:8080/ -o /dev/null & done; wait

Why fork()?

Forking gives each request a separate address space, which is the simplest way to get strong isolation. The cost is higher per-connection overhead than threads or a thread pool, which production servers use instead. This project trades raw performance for clarity: it shows exactly how sockets, processes, file I/O and signals fit together.
